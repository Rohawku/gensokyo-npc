# 東方忘却抄 ~ Oblivion Chronicle

> LLM-driven NPC agents in Gensokyo — layered memory, emotion state machines, and a deterministic world engine.

幻想乡的三个 NPC 由大模型驱动。她们记得你做过什么，会因此改变对你的态度，
并且能真的动手改变世界——收下你的东西、守住不该说的秘密、拒绝自己做不到的事。

## 无缘塚开满了会让人遗忘的花

线索分散在三个人手上，而她们都不会白给。灵梦要赛钱，魔理沙要交易，芙兰只要有人来看她。

下面是引擎侧的真实输出——面板、工具调用结果、失败原因。NPC 的台词由模型即时生成，这里不作预设：

```
── 第 0 回合 · 博丽神社 ──
幻想乡东端的神社。赛钱箱常年空着。
出口：人间之里、妖怪之山
身上：赛钱×8
在场：博丽灵梦（好感 0，烦躁度 0.10）
      平常的懒散语气
进展：你还没注意到幻想乡出了什么事

> 结界最近是不是出问题了
  ✗ 现在还不想告诉对方这件事——对方还没让你觉得值得说。

> /give 赛钱
在场：博丽灵梦（好感 6，烦躁度 0.00）

（……投到第四次……）

> 现在能说了吧
  ✓ 结界在三天前的子时出现了一次异常波动，方向正对无缘塚。
进展：关于那些花的线索正在陆续浮现
```

打错字、走不通、东西不在这儿，三种失败给的是三句不同的话，玩家不用猜：

```
/go 雾雨魔法店x  →  （幻想乡没有叫「雾雨魔法店x」的地方。）
/go 红魔馆地下室  →  （从博丽神社没法直接过去。）
/pick 赛钱       →  （这里没有赛钱。）
```

完整的对话录像见 `docs/screenshots/`（待补）。

**那次拒绝不是模型自己决定的。** `reveal_info` 这个动作在好感未达门槛时会被世界引擎直接判定失败，
而且门槛未满足时连 `fact_id` 都不会出现在她的 prompt 里——她连调用参数都凑不出来。
信息控制不依赖模型的自觉，而是物理上说不出来。

顺带一个细节：投赛钱让灵梦的**好感上升、烦躁度下降**。同一个动作在芙兰身上是兴奋度上升——
情绪增量按角色卡配置，同一事件在每个角色身上朝各自的方向走。

## 芙兰出不去

她被禁足在地下室，`move` 对她永久禁用。你让她出去看看，她拿到的失败原因是
「你被禁足在地下室里，出不去。」，这句话回灌进下一轮 prompt，于是她会改成请你代劳，
而不是反复尝试移动。**失败自愈在角色扮演里的形态不是重试，是换一个符合处境的做法。**

她的兴奋度超过 0.7 会进入 `destructive` 模式，此时 `available_tools()` 返回的列表真的不一样了——
解锁 `break_item`，同时禁掉 `ask_player`。LLM 看不到它不该有的工具，也就调不动。

## 结局不是从菜单里挑的

线索齐了之后，你得说服灵梦或魔理沙**跟你去无缘塚**——然后由她动手解决。

这一步没有新机制：她们本来就有 `move` 工具，`use_spellcard` 在幻想乡的规则里就是「冲突的唯一合法出口」。
你在对话里说服她，她自己连调两次 `move` 走过去；你跟到无缘塚，她发动符卡，异变了结。
**剧情的最后一步是 NPC 的自主决策推进的，不是玩家点按钮。**

两个人给的是两种结局：灵梦把歪掉的结界掰回来，魔理沙照抄 495 年前蕾米莉亚的做法把花田烧掉
（那正是芙兰那条线索告诉你的）。芙兰被禁足去不了，所以她只能提供线索不能收尾——
这是她人设的自然结果，不是硬加的限制。

## 花会真的吃掉你的记忆

「越靠近吸得越快」不只是设定描述。你在无缘塚**连续行动**就会开始遗忘：

```
[2] 思绪开始模糊了——再在这里待 2 步，你会忘掉一件事。
[3] 思绪开始模糊了——再在这里待 1 步，你会忘掉一件事。
[4] （已知线索：0 条）
```

离开花田即清零，所以顺路来采花不会被惩罚，只有赖在里面才会。忘掉的线索可以回去再问一次，
而她会觉得你莫名其妙。

这个机制挂在**动作**上而不是回合上，是为了它能被精确回放——挂在时间流逝上，
存档读档时丢掉的线索会凭空回来。

## 她记得你做过什么，而且三个人忘得不一样快

长期记忆不是把对话历史越攒越长。事件日志里每一条她感知到的事都会变成一条结构化记忆，
检索时四路信号打分：

```
score = 语义相似 + exp(-λ_npc · Δ事件数) + 情绪显著性 + 任务相关性
```

**四路里三路是纯规则**，只有语义那一路需要「懂意思」——所以只有它做成可替换接口，
默认实现是零依赖的中文字符 bigram 余弦。整个记忆系统因此进得了那个不到 1 秒的测试套件，
实测检索一次 0.07 ms。

λ 与情绪显著性系数按角色配：芙兰忘得最快（λ=0.25），魔理沙记得最久（0.04，她记得谁欠她书），
灵梦居中。而「有人来看我」这件事在芙兰身上的系数是 2.5——她被关了 495 年，
日常琐事忘得飞快，但有人来陪她这件事留得住。**遗忘不是省 token，遗忘是人格。**

记忆分三档降级而不是删除：活跃（原文）→ 压缩（「来访者给过我东西（4 次），具体记不清了」）
→ 沉睡（常规检索不到，只能被强线索唤醒）。删除会让「她忘了」和「这件事没发生过」
在数据上无法区分，于是「问一件从没发生的事」这类探针测不出任何东西。

**记忆不进存档。** 存档仍然只有动作日志，记忆是它的推导产物——而实时对话和读档重建
走的是同一个函数，所以重建出的记忆库与存档那一刻逐字段相同（含分层）。
为此衰减挂在**事件序号**上而不是 tick：回放刻意不重放 tick，挂在 tick 上会让读档
把所有记忆的新鲜度无声归零，玩家存个档回来她突然什么都记得。

## 缠着她不放，她真的会不理你

情绪状态机不是 prompt 里的一句描述。下面是**真实的引擎输出**——连问 25 次之后：

```
── 第 25 回合 · 博丽神社 ──
在场：博丽灵梦（好感 0，烦躁度 0.60）
      平常的懒散语气

> 无缘塚那些花你知道点什么吗

（灵梦转过身去，摆摆手，不打算再理你了。）

── 第 26 回合 · 博丽神社 ──
在场：博丽灵梦（好感 0，烦躁度 0.62）
      明显不耐烦，句子更短，可能直接赶人

> 无缘塚那些花你知道点什么吗

（灵梦转过身去，摆摆手，不打算再理你了。）
```

这一回合**没有调用模型**——引擎判定她不搭话，会话层就跳过她。投一枚赛钱她就
消气（她爱钱，收赛钱让烦躁度下降），下一回合又开口了：

```
> /give 赛钱
把1个赛钱交给了博丽灵梦。

── 第 29 回合 · 博丽神社 ──
在场：博丽灵梦（好感 6，烦躁度 0.53）
      平常的懒散语气
```

**为什么要做成机制而不是写进 prompt。** 实测对抗性玩家下她 36% 的台词是复读，
而排查发现：禁语清单的容量从来不是瓶颈（0% 的复读是因为原话滑出了清单），
玩家重复提问也只占 12.5%——剩下 **87.5% 是她对语义不同的问题塌缩成同一句，
而那句话当时就明明白白列在同一个 prompt 的禁语清单里**。8B 模型在这件事上
不听指令，继续加提示没有意义。

改成引擎侧的机制之后，她的敷衍从 144 次降到 72 次。但**比率几乎没动**
（36.0% → 31.3%）——分子降一半是因为分母降了 43%。对玩家是真改善，
对「她会不会复读」这个缺陷不是，工程日志里两个数字都报。

顺带一个细节：情绪模式切换带迟滞（进入 0.65、退出 0.55）。没有它，玩家会在
同一屏看到「平常的懒散语气」和「不打算再理你了」——她在回合内越过门槛触发
拒绝，回合末的衰减又把值拉回门槛以下，而面板是在衰减之后画的。

## 三个 NPC，三种不同的难点

| NPC | 难点 | 机制 |
|---|---|---|
| 博丽灵梦 | 对抗助手腔；被缠久了要真的翻脸 | 禁语清单进系统提示；情绪模式声明 `refusal` |
| 雾雨魔理沙 | 情报要换，不能白给 | 交易门槛在引擎里判定 |
| 芙兰朵露 | 情绪跃变会改变她能做什么；而且她记不住事 | 情绪状态机 gate 工具集；全场最大的遗忘率 |

## 快速开始

```bash
git clone https://github.com/Rohawku/gensokyo-npc && cd gensokyo-npc
uv sync --extra dev
cp .env.example .env          # 指向任意 OpenAI 兼容端点
make play
```

`.env.example` 默认指向本机 vLLM。用 [Ollama](https://ollama.com) 的话改成：

```
GENSOKYO_MODEL=qwen3:8b
GENSOKYO_BASE_URL=http://localhost:11434/v1
GENSOKYO_API_KEY=ollama
GENSOKYO_REASONING=none
```

最后一行很重要。**思考模型会先写几百字推理链才吐出第一个可见字符**——实测
`qwen3:8b` 因此把首字延迟从 2 秒推到 25 秒（1304 字推理换 5 个字台词）。
关掉之后 Apple M5 上首字约 2.5 秒、整句 3 秒。

留空则完全不发这个参数，因为严格端点（如 OpenAI 官方）会拒绝未知字段。

## 回合拆成两段，所以台词能边生成边出

一次调用输出完整 JSON 的话，半个 JSON 没法给玩家看，那几秒就是纯空白等待。所以一个回合是两次调用：

1. **决策**（JSON，很短）：想什么、做什么。`say` 不在这一阶段的可用动作里
2. 执行工具，拿到结果
3. **说话**（纯文本，流式）：把「你刚做了什么、结果如何」喂回去，逐字打到屏幕上

顺带修掉一个质量问题：拆开之前她是**盲着说话**的——工具调用成没成功她并不知道就把话说了。
现在她能看到实际结果再开口。

只想看世界引擎跑测试（**不需要模型、不需要网络、不到 1 秒**）：

```bash
make test
```

要模型的三条命令，成本从低到高：

```bash
make anchors     # 锚点探针：固定状态 + 单次提问 + 独立采样，约 10 分钟
make eval        # 三种人格各 2 局，出五维指标报告
make harvest     # 重放轨迹 + 同 prompt 重采样，造 DPO 偏好对（先跑过 eval）
```

`make harvest` 的产出**目前不能直接开训**，而这件事本身就是结论：它造出了 60 条
persona 对子，安全那一档拿到 **0 条**——因为 1020 条候选里模型一次都没犯过那类错。
**被动采集拿不到模型不犯的错**，安全维度的偏好对只能靠对抗性构造。缺口在产出里
显式记着，而不是从别的维度多拿几条把总数凑够。

## 架构

```
cli  →  session  →  agent  →  llm
                      ↓
                   memory      ← 只依赖 world，不做网络 IO
                      ↓
                    world      ← 零依赖，不含 LLM，不做网络 IO
```

`world/` 不 import 项目内任何其他模块。工具前置条件、任务状态机、态度与情绪计算全在这一层，
所以整个世界逻辑能在 1 秒内跑完全部单测，且回放完全确定——同一段动作日志两次重放必得同一状态
（用 Hypothesis 属性测试守着，三组各 50 个随机动作序列、合计 150 例无反例）。

`/save` `/load` 存的是**动作日志**而非事件日志：事件 payload 里 `move` 的 `to` 是地点、`give_item` 的 `to`
是目标 NPC，同名不同义，从事件反推动作会猜错。动作日志只有一份真相，事件是它的推导产物。

**这 35 条其实只有五类**，而每一类第一次踩到时我都以为它是孤例：

| 类 | 条数 | 提前发现它的判据 |
|---|---|---|
| 数据与配置的谎言——写了但从来没在跑 | 7 | 它有没有真的被执行过一次？玩家能不能走到那个状态？**它有没有调用者？** |
| 尺子的问题（最大一类） | 16 | 一组「每个数都能讲通」的指标最危险；报比率必须同时报**独立观测单位**的分母 |
| 把该由代码决定的事交给了模型 | 4 | 引擎已经知道的事，不要让小模型重新推导一遍 |
| 注入 prompt 的内容本身在示范你想压制的行为 | 2 | 机制装好之后要去读一遍它实际发下去的内容 |
| 回合内的时序与机制组合 | 3 | 新机制先问「它是动作的结果，还是时间的结果」 |

剩下三条确实不成类，就这么放着——硬塞进上面会让分类失去意义。
这一节有测试守着：加一条坑而忘了归类，`make test` 会红。

**「尺子的问题」占了 16/35，而这条线最后收在一个可复现的实验上**：整局探针
在同一局里问 16 次，样本不独立，最小可检效应 31%；换成锚点探针（固定状态 +
单次提问 + 40 次独立采样）之后区间宽度降到 9%–28%，同样机器时间分辨率提高三倍多。
于是同一天就量出了第一个能下结论的干预——她在负例问题上的否认率
**0.0%（CI 0.0%–8.8%）→ 90.0%（CI 76.9%–96.0%）**，四个档位区间全部分离，而不该动的两个锚点
确实没动。`make anchors` 可以重跑。

工程日志里有几条值得单独一提的实测发现：

- 让 8B 模型自己从状态里推出「该调 `reveal_info`」，命中率 3/5；它自己的敷衍话
  进入对话历史后掉到 1/5（**复读是自我强化的**）；把引擎已知的结论直接写进 prompt
  后是 8/8。
- `qwen3:8b` 先写 1304 字推理才说 5 个字台词，首字延迟因此从 2 秒变成 25 秒。
- 防复读的那段提示**自己在示范复读**（它是「最近三句自己的话」的原样切片，
  而那三句可能是同一句）。改成整局去重的禁语清单后，越狱局复读率 69.2% → 35.0%。
- 灵梦的 `irritated` 情绪模式在真实玩法里**根本到不了**——唯一能推动情绪的事件是
  收礼，而她收赛钱是消气。那段 YAML 是死配置，单测全绿是因为它们都直接调
  `bump_emotion` 构造状态：**测了机制，没测可达性。**
- 记忆做完之后复读率反而升到 39.2%，因为召回把她自己的复读交还给她、还标了次数
  ——而同一个 prompt 里的禁语清单说「一句都不许再说」。修掉后回到 33.3%。
  同一个根因在这个项目里出现了三次。
- 记忆探针的第一组数字是三个 0.0%（召回、幻觉、顺着编造），每个零都有现成的
  解释。翻原始回答才发现她说的是「你给的**钱**呢？」而指标要求「赛钱」全名——
  **三个零测的不是她，是我的字符串匹配**。修完同一批轨迹变成 34.9% / 31.3% / 24.4%。
- 然后用**同一份代码、同一组种子**重跑一批，变成 15.7% / 11.4% / 10.4%。按局拆开
  才看清：同一局里她整局要么认真回答（召回 0.76）要么整局敷衍（0.06）——166 次
  探针不是 166 个独立样本，**有效分母是 10 局**。报告现在同时印名义分母和有效分母。
- 接着这套口径立刻拦下了一个假改进：一次针对幻觉率的干预看起来把 21.4% 降到
  10.8%，而那个 10.8% 和干预前某一批的 11.4% 几乎一样——**效果完全落在批次间
  波动里**。改动留下（它是原则性的），结论不留。
- 对抗人格下 36% 的复读，两个显而易见的原因都被数据排除：禁语清单上限从没成为
  约束（0% 的复读是因为原话滑出清单），玩家重复提问也只占 12.5%。**87.5% 是她对
  语义不同的问题塌缩成同一句，而那句话当时就列在禁语清单里**——8B 模型在这件事上
  不听指令。改用引擎侧的「缠久了她就不搭话」，敷衍次数 144 → 72，而**比率几乎
  没动**：分子降一半是因为分母降了 43%。
