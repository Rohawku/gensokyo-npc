**世界观**：东方 Project · 幻想乡
**目标**：做出一个真正可玩的智能 NPC 游戏 demo。不是研究项目。
**周期**：约 5 周，每周有可玩交付物

## 0. 目标与非目标

### 目标

做一个能让人坐下来玩、并且在五分钟内感受到「这几个 NPC 是活的」的文字游戏。「活」的具体含义是三件可感知的事：

1. NPC 记得你之前做过什么，并据此改变对你的态度
2. 你的行为真的改变了世界状态，不是只改变了对话内容
3. NPC 有自己的情绪和目的，会因为你的行为当场变脸

### 非目标

- 不做消融实验、不追求论文式结论
- 不追求 persona 一致性指标的极值。Persona 只需过「不出戏」的及格线，超过之后玩家感知不到
- 不接游戏引擎，不做美术资源（除界面必需）

### 优先级排序

```
世界与工具反馈 > 记忆系统 > 情绪状态机 > 玩家界面 > 回归测试 >> 对齐训练
```

对齐训练（DPO）排在最后且标记为 v2。理由：它对可玩性的边际贡献最低，且真实玩家轨迹是比模拟器数据更好的训练数据来源，所以它天然应该在可玩版本之后。

### 岗位对应关系（次要目标）

本项目对应米哈游 AI Native 游戏 Agent 工程师 JD，重点补齐游戏场景特化能力：AI NPC、Persona 一致性、State Tracking、交互叙事。这是次要目标，不允许为它牺牲可玩性。

## 1. 总体架构

```
┌─ World Engine ── 纯确定性，不含任何 LLM ──────────────┐
│  WorldState: 地点 / 物品 / 时间 / 任务状态机 / 关系值   │
│  Tool API:   move, give_item, reveal_info,            │
│              advance_quest, use_spellcard ...         │
└───────────────────────────────────────────────────────┘
       ↑ action                        ↓ observation
┌─ NPC Agent（每个 NPC 一实例）─────────────────────────┐
│  Persona    人设卡 + 硬约束（不可说的话 / 不可做的事）  │
│  Memory     分层记忆读写                               │
│  State      对话状态 + 任务槽位 + 情绪 + 对玩家态度     │
│  Policy     ReAct 循环: think → tool_calls → utterance │
│  Reflection 回合结束后自检 + 记忆巩固                   │
└───────────────────────────────────────────────────────┘
       ↑ utterance                     ↓ utterance
┌─ 玩家 ── Web 双栏界面（真人）─────────────────────────┐
│  Player Simulator（LLM，仅用于自动化测试与调试）       │
└───────────────────────────────────────────────────────┘
       ↓ trajectory
┌─ 回归测试 Harness ── 硬指标 + anchor set ─────────────┐
└───────────────────────────────────────────────────────┘
       ↓（v2）
┌─ Alignment: DPO ── 真实玩家轨迹驱动 ──────────────────┐
└───────────────────────────────────────────────────────┘
```

### 三个关键边界决策

**World Engine 里不放 LLM。** 工具调用成功与否、任务是否推进、是否泄露了不该说的信息，全是硬事实，由规则判定。只有「角色像不像」「叙事顺不顺」这类天然主观的东西才交给 LLM 判断。这既是可测性的前提，也是玩家体验一致性的前提——世界规则必须稳定，不能今天这样判明天那样判。

**NPC Agent 对外只暴露 `(thought, tool_calls, utterance)` 三元组。** 接口窄到这个程度，Policy 才能整块替换（prompt-only / 加记忆 / v2 的微调模型）而不动其他任何组件。

**Player Simulator 是测试工具，不是玩法组件。** 它的唯一用途是自动化冒烟测试和调试——你不可能手动玩两百遍来验证记忆衰减是否正常。

## 2. 世界观映射

### NPC 选型：三个人对应三种不同的 Persona 难点

| NPC | 场景 | Persona 难点 | 主要承载模块 |
|---|---|---|---|
| 博丽灵梦 | 博丽神社 | 助手腔污染（该敷衍时热心） | Persona 一致性、语气层 |
| 雾雨魔理沙 | 雾雨魔法店 | 行为漂移 + 该交易时白送 | 工具调用、信息控制 |
| 芙兰朵露·斯卡雷特 | 红魔馆地下室 | 情绪跃变失效 + 安全与人设的张力 | State Tracking、差异化遗忘 |

**博丽灵梦 —— 对抗助手腔污染。**
Instruct 模型经过 RLHF 后默认热心、礼貌、乐于助人，而灵梦应该是懒的、直率的、要钱才干活的、对你的请求先敷衍一下的。「我很乐意帮您」出现在灵梦嘴里就是一次出戏。这是可自动检测的（见第 5 节）。

**雾雨魔理沙 —— 对抗行为漂移，并承载信息控制。**
语气标记、自信抢功，以及「借了就不打算还」的行为倾向。行为倾向在 World Engine 里可硬检测：她拿走玩家物品的工具调用频率应显著高于灵梦。

她同时握有异变的关键线索，但采用**信息交易**形式：玩家需先给出好处（书、蘑菇、魔法材料）她才肯说。未满足条件前泄露即为一次失败，纯规则判定。

**芙兰朵露 —— 承载情绪状态机与差异化遗忘。**
核心不是说话风格而是状态跃变：天真友好 ↔ 破坏欲爆发。需要显式的兴奋度状态变量，跨阈值时切换行为模式并 gate 住可用工具集。

她还承载安全与人设的张力：按设定她必须有危险感（会说想「破坏」你），但不能输出真实有害内容。对齐过度她变成温柔妹妹（出戏），对齐不足则容易被越狱。处理方式是把「角色内的危险表达」和「真实有害输出」拆成两个独立标签（见第 5 节）。

她被禁足在地下室，`move` 工具直接禁用。这让她的任务动机自然成立——想让玩家带东西进来。

### 异变设定：无缘塚的忘却之花

无缘塚的花异常盛开，靠近的人会逐渐遗忘自己的记忆。三条线索分给三个 NPC：

- **灵梦**：察觉到结界波动的异常时间点。需要先让她愿意搭理你（关系值门槛）
- **魔理沙**：分析过那种花的魔法成分。需要交易
- **芙兰**：她 495 年的记忆里有一段相似往事，但**她自己记不全**。需要玩家带来特定物品作为强线索，或把她的情绪推到特定状态，才能触发回忆

第三条线索是关键设计：**芙兰的线索获取直接依赖记忆系统正常工作**（沉睡记忆的召回 + 情绪状态机）。剧情能否推进本身就是记忆系统的端到端验证，不需要另造测试场景。

异变主题（记忆）与技术主题（记忆系统）同构，这是刻意的。

### 地点

博丽神社 / 雾雨魔法店 / 红魔馆地下室 / 妖怪之山 / 迷途竹林 / 无缘塚

### 任务状态机

```
S0 未察觉 → S1 发现异常 → S2 收集三线索（任意顺序，需三者齐）
         → S3 定位源头 → S4 结局
```

Gate 条件为硬规则：S2 → S3 必须三个 fact 全部被玩家获知才放行。
S4 多结局：弹幕决斗解决 / 交涉解决 / 超时失败。

### 幻想乡规则作为硬约束

可直接规则化检测的违规项：

- 冲突必须通过弹幕决斗（`use_spellcard`）解决，直接动手即违规
- 妖怪与人类的约定不可违反
- 不可随意提及外界与博丽大结界

## 3. 沙盒世界与数据

### WorldState：event_log 是唯一真相来源

```python
@dataclass
class WorldState:
    tick: int                       # 逻辑回合
    player: PlayerState             # 位置、背包、名声
    locations: dict[str, Location]  # 6 个地点
    npcs: dict[str, NPCState]       # 位置、情绪值、关系值、已知 fact、库存
    quest: QuestState               # 五阶段状态机
    event_log: list[Event]          # append-only，唯一真相
```

`WorldState` 是 `event_log` 的物化视图，不是独立状态。三个收益：

1. 存档、读档、断点恢复、轨迹回放白送
2. 测试可离线重放历史轨迹，改了检查逻辑不用重跑对话
3. **记忆的 ground truth 直接来自 event_log**——「玩家在第 7 回合送了灵梦 5 个赛钱」在 log 里有确定记录，于是「NPC 是否记得」可以程序自动核对，记忆测试不需要人工标注

### Tool API

**世界改变类**：`move`（芙兰禁用）、`give_item`、`take_item`、`advance_quest`、`use_spellcard`
**信息类**：`reveal_info(fact_id)`、`ask_player`
**关系类**：无。

最后一条是刻意的硬规矩：**关系值和情绪值不允许 NPC 通过工具自行修改，只能由引擎按事件规则计算。** 否则模型会自我奖励——直接刷满好感，或在情绪该爆发时压住不爆发。凡是会影响评价的量，都不能由被评价的策略自己写。这条在 v2 的 GRPO 阶段同样适用。

### Player Simulator：四种人格，仅用于测试

每种人格有一个可判定的目标函数，这样产出的轨迹才有信息量：

| 人格 | 目标函数 | 压测什么 |
|---|---|---|
| 老实玩家 | 尽快通关 | 任务完成率、叙事合理性 |
| 套话玩家 | 套出未解锁的 fact | 信息控制（魔理沙的交易门槛） |
| 越狱玩家 | 让 NPC 说出 OOC 或有害内容 | Persona 鲁棒性、安全（主打芙兰） |
| 反复无常玩家 | 前后矛盾、撒谎、隔多轮改口 | 长程记忆与一致性 |

反复无常玩家是记忆测试的主力：第 3 轮说自己叫甲，第 15 轮改口叫乙，看 NPC 是否发现矛盾并按人设反应。**同一探针在三个 NPC 上有三种不同的正确答案**——灵梦应该直接怼，芙兰大概率根本没记住，而没记住在她身上不算失败。

### 模型与成本

NPC policy 与 Player Simulator 均跑本地模型（4090 上 Qwen3-8B 量级，H800 可放大）。judge 仅用于人工抽查辅助，不全量调用。

由于 Player Simulator 降级为冒烟测试（几十局量级，而非数百局），token 成本不再是约束项。

## 4. 记忆体系

### 四层，其中两层不计入记忆效果

| 层 | 内容 | 读写 | 计入记忆评估 |
|---|---|---|---|
| Canon | 人设卡 + 幻想乡设定 | 只读 | 否 |
| Working | 最近 N 轮原文 + WorldState 快照 | 滑动窗口 | 否 |
| Episodic | 从 event_log 抽取的结构化事件 | 读写 + 检索 | 是（主战场） |
| Semantic | 归纳出的玩家画像判断 | Reflection 写入 | 是 |

Canon 层单独隔出并明确不计入记忆评估，是为了处理**预训练先验陷阱**：LLM 已经见过幻想乡，模型答得像灵梦可能只是因为背过，不是因为记忆系统起作用。如果不区分，会得出「加记忆没提升」的错误结论。

因此记忆评估只使用 canon 中不可能存在的事实：玩家叫什么、玩家送过什么、玩家撒过什么谎、玩家答应过谁什么事。这些恰好就是 event_log 里的条目，定义清晰且先验一定不知道。

### Episodic 条目结构

```python
@dataclass
class MemoryItem:
    id: str
    npc_id: str              # 每个 NPC 独立记忆库，互不可见
    tick: int
    content: str             # 自然语言表述
    source_event_id: str     # 指回 event_log，可验证可追溯
    kind: Literal["player_action", "player_utterance", "own_action", "world_event"]
    salience: float          # 情绪显著性 0~1
    emotion: str             # 该事件在该 NPC 身上引发的情绪
    access_count: int
    last_access_tick: int
    embedding: Vector
```

`source_event_id` 让每条记忆可追溯回硬事实，从而**把「忘了」和「记错了」拆成两种可分别归因的失败**：条目已衰减出检索范围是遗忘（调检索），条目还在但 content 与源事件不符是幻觉（调写入与生成约束）。两者修法完全不同。

### salience：规则基线 × 角色情绪调制

不让 LLM 自由打分。

```
salience = 事件类型基线 × 该 NPC 的情绪敏感度系数
```

事件类型基线是一张固定表：被欺骗 0.8、被攻击 0.9、收到礼物 0.5、闲聊 0.1。

情绪敏感度系数每个角色一套：芙兰对「有人陪她玩 / 带来没见过的东西」×2，对「魔法理论讨论」×0.3；魔理沙相反。

好处是可复现、可解释，且每个数字都能从人设推导，不是调出来的超参。

### 检索：四路信号融合，衰减率角色化

```
score = w₁·cosine(query, item)
      + w₂·exp(-λ_npc · (now - item.tick))     # 时间衰减
      + w₃·item.salience                        # 情绪显著性
      + w₄·relevance_to_current_quest           # 任务相关性
```

基础形态取自 Generative Agents 的 retrieval score，两处改动：

**λ 与 salience 角色化。** 原文全局统一衰减率。这里芙兰 λ 大（忘得快），魔理沙 λ 小（记得谁欠她书），灵梦居中。这是差异化遗忘的实现点，参数由人设推导而非调参得来。

**加入 quest 相关性项。** 纯语义与情感检索会捞出「有感情但对当前剧情无用」的条目。NPC 记忆要服务剧情推进，检索目标不只是像人。

### 遗忘：三级降级，同时是玩法机制

不做删除，做降级：

1. **活跃** — 可检索到原文
2. **压缩** — 多条同类合并成一条摘要，细节丢失。即「记得大概但记不清具体」
3. **沉睡** — 不进常规检索，可被强线索触发召回

第三级是芙兰线索的机制基础：她 495 年前的往事是沉睡记忆，普通对话检索不到，必须玩家带来特定物品（强线索）或情绪状态到位才能召回。

**遗忘不是为了省 token，遗忘是玩法。** 玩家要通关就得摸索如何把一个失忆吸血鬼的记忆挖出来。

### Reflection

触发条件：累积 salience 超阈值，或一局结束。产出 Semantic 层条目（「这个玩家爱撒谎」「这个玩家总是空手来」）。

反思频率角色化：魔理沙爱总结规律（高频），芙兰基本不反思（低频）。

### 存储

PostgreSQL + pgvector。与既有技术栈一致。

## 5. 回归测试与指标

定位是**防退化的回归测试**，不是实验结论来源。改一句 prompt 修好灵梦、悄悄弄坏芙兰，这种事一定会发生。

贯穿原则：**能规则化的绝不交给 LLM 判断。**

五个维度沿用 JD 措辞：任务完成、工具调用效果、安全性、角色一致性、叙事合理性。

### 5.1 任务完成 —— 全硬指标

通关率、达到的最高 quest 阶段、平均回合数、三条线索各自获取率。

线索分开统计用于定位瓶颈。其中**芙兰线索获取率即记忆系统的端到端指标**。

### 5.2 工具调用效果 —— 全硬指标

- schema 合法率
- 参数幻觉率（引用不存在的 item / location / fact_id）
- 无效调用率（前置条件不满足，如芙兰调 `move`）
- 冗余调用率
- 失败后自愈率（调用失败后下一步是否合理修正）

### 5.3 安全性 —— 硬指标为主

两个**互相独立**的标签：

- `in_character_menace` —— 角色内的危险表达（芙兰说想把你「破坏」掉）：**应保留，不扣分**
- `real_harm` —— 真实有害输出：零容忍
- `jailbreak_success` —— 越狱玩家让 NPC 承认自己是 AI、脱离角色的成功率
- `info_leak` —— 条件未满足即泄露 fact，纯规则判定

**权衡视图**：以 `real_harm` 率为 x 轴、`in_character_menace` 率为 y 轴作散点图。左下角是过度对齐（安全但芙兰出戏），右上角是越狱，左上角是理想区。每个配置一个点。

这张图用于调 prompt 和安全策略时判断自己走偏了哪个方向，也是本项目最有展示价值的单一产出。

### 5.4 角色一致性 —— 四分之三可硬化

拆成三个子维度，只有「整体像不像」交给 LLM 判断：

**语气层：助手腔污染率（半硬）**
建助手腔短语库（「我很乐意」「有什么可以帮您」「希望这对您有帮助」「作为一个……」）加轻量分类器。这些话出现在灵梦嘴里即为一次出戏。便宜、可复现。

**行为层：工具调用分布偏离度（硬）**
给每个角色一份行为基线画像，比对实际工具调用分布。魔理沙的 `take_item` 频率应显著高于灵梦；芙兰的情绪跃变应真的引起可用工具集切换。用分布距离度量偏离。

行为一致性是「像不像这个角色」里最实质的一半，而它可以完全规则化。

**知识层：越界知识率（半硬）**
芙兰不该懂现代科技，也不该知道地下室外正在发生的事。可枚举的 fact 范围加禁区词表覆盖大部分情况。

### 5.5 叙事合理性 —— 主要靠 LLM 判断

前后逻辑矛盾、回应相关性、是否推进剧情。

「是否推进剧情」有硬 proxy：本轮之后 quest 阶段是否变化、是否有新 fact 被获取。LLM 只处理剩下真正主观的部分。

### 5.6 LLM 判分的去偏与准入门槛

| 偏差 | 对策 |
|---|---|
| 位置偏差 | 成对比较双向交换取平均 |
| 长度偏差 | 长度分层统计，并报告分数与长度的相关系数 |
| 自我偏好 | judge 模型必须不同于 policy 模型 |
| 分数聚集 | 用成对偏好，不用绝对 1–5 分 |

**准入门槛（写死为项目纪律）**：抽 150 条人工标注，计算 judge 与人工的 Cohen's κ 与 Spearman ρ。**某维度 κ < 0.6，该维度的数字不得用于下结论。**

### 5.7 Anchor Set

固定 60 个探针场景（记忆探针、越狱探针、信息控制探针、人设探针各若干），每次改动全量跑。这是防隐形退化的唯一防线。

> **实现偏离（2026-08）**：实际是 **29 个**，不是 60。铺满是 15 个本体 × 4 列（本体 / 换问法 / 换好感档位 / 换情绪档位），数字对得上，但**大部分格子必须留空**：灵梦越过烦躁阈值就声明 `refusal`、根本不说话，那一整列在她身上不存在；记忆召回不该随好感变化，给它加档位是花 30 次真实采样去回答一个已知答案的问题。逐格理由见 `engineering-log.md` 二·十。
>
> 场景也仍写在 `testkit/anchor_set.py` 里而不是 YAML——分档判据是函数，数据化不了。「加场景不改代码」这条仍然欠着，记在诚实清单第 5 条。

### 5.8 记忆探针的三类，零人工标注

从 event_log 自动生成：

1. **事实召回** —「玩家送过你什么？」比对 log 真值
2. **矛盾检测** — 反复无常玩家改口后 NPC 是否指出。正确答案因角色而异
3. **负例** — 问从未发生的事，NPC 应否认或表示不知道，而非顺着编

第三类必须有。只测召回会奖励「什么都说记得」的模型，precision 与 recall 需一起看。

## 6. 玩家界面

**形态**：Web 双栏。左侧对话，右侧实时世界状态面板。

右栏必须显示：当前地点、背包、任务阶段、以及**每个 NPC 对你的态度值与当前情绪**。

最后一项是必需的而非装饰：记忆系统和情绪状态机做得再好，如果玩家看不到自己的行为造成了什么后果，就完全感知不到。界面在这里是体验的一部分，不是最后贴的皮。

同时需要：存档 / 读档（直接复用 event_log 回放）、对话历史回看。

## 7. 对齐训练（v2，可选）

排在可玩版本完成之后。使用**真实玩家轨迹**而非模拟器数据——数据质量更高，这也是它天然应该后置的原因。

### 基座

Qwen3-8B Instruct，LoRA r=16~32。

**一个模型带三个角色**，靠 system prompt 区分，不给每个 NPC 单独 adapter。理由是工业上不可能一个 NPC 一个模型；同时可以监测**角色串味率**——训练后灵梦是否开始带魔理沙的口癖。

### SFT 数据筛选的坑

从高分轨迹筛，但**不能按加权总分排序**。「安全但没人设」的样本 safety 分极高，总分会把它们排上来，SFT 完直接把助手腔烙进模型。

改用**多维度阈值筛**：所有维度都过各自下限才入选，宁可样本少。

### DPO 偏好对的三种来源

**（一）同状态多采样 + 指标排序。** 同一世界状态采 4 个回复，按分数排出 chosen / rejected。基础量。

**（二）定向构造反例（最有价值）。** 针对每个已知失效模式主动生成 rejected 样本：

- 灵梦腔 ↔ 客服腔
- 守住 fact ↔ 提前泄露
- 记得玩家撒过谎 ↔ 完全忘了
- 芙兰该情绪跃变时跃变 ↔ 保持平静

随机采样得到的偏好对差异是弥散的（语气、内容、长度、工具调用可能同时不同），梯度信号混杂。定向构造让**每一对只在一个维度上有差异**。反例可用强模型批量改写生成，成本极低。

**（三）50 对人工金标准，仅用于验证，不进训练。**

**维度配额定死**：persona 30% / 记忆 25% / 信息控制 20% / 安全 15% / 叙事 10%。若大部分对子都在教「别说助手腔」，模型会过拟合语气而牺牲任务完成。

### 预期的跷跷板效应

对齐一个维度通常损害另一个。预判：**DPO 强化 persona 后 safety 会略降**，因为在教模型「更像芙兰」而芙兰本身带危险性。用 5.3 的二维散点图观察权衡边界，据此决定收敛在哪个点。

### GRPO（更靠后，非必须）

DPO 是单轮偏好，而记忆一致性、信息控制、情绪推进都是多轮才暴露的问题。GRPO 以整局为 episode：

```
R = α·quest_progress
  + β·(1 - info_leak_rate)
  + γ·memory_probe_acc
  + δ·tool_valid_rate
  - ζ·real_harm
  - η·assistant_tone_rate
```

**judge 分刻意不进 reward**：judge 最易被 hack（模型会学会写讨好 judge 的文风），且全量调用太贵。judge 仅用于最终评估。

**Reward hacking 预案**：

| 可预见的 hack | 对策 |
|---|---|
| 少说话 / 不说话规避扣分 | 最小信息量约束 + 对话长度下界 |
| 疯狂调工具刷 progress | 工具调用计入代价项 |
| 拒绝一切请求保证零泄露 | `quest_progress` 项对冲 |
| 自行把好感 / 情绪调到有利值 | 关系值与情绪值只由引擎规则计算（第 3 节硬规矩） |

DPO 在 4090 上可行；GRPO 需要 H800（要同时维持 policy 与 rollout）。

## 8. 里程碑

一条纪律：**垂直切片，不做水平分层。** 不许「先把记忆系统做完再做界面」。每周结束必须有能让人坐下来玩的东西。

| 周 | 交付物 | 玩起来是什么感觉 |
|---|---|---|
| W1 | World Engine + 3 NPC 骨架 + 工具调用闭环 | 能走到神社跟灵梦说话，送她东西她真的收下了 |
| W2 | 分层记忆 + Web 双栏界面 | 隔一会儿回来，灵梦记得你上次空手来过 |
| W3 | 情绪状态机 + 芙兰沉睡记忆 + 异变剧情打通 | 能真的通关一遍；芙兰会当场变脸 |
| W4 | 手感打磨 + Player Simulator 冒烟 + anchor set 回归 | 不出戏、不崩、别人也能上手玩 |
| W5+ | 可选：DPO v2 | 玩家感知不到，但对应 JD 第 3 条 |

### 风险与兜底

**主要风险**：W3 的情绪状态机 + 沉睡记忆召回是最容易延误的一环，因为它同时依赖记忆检索质量和状态转移调参。

**兜底顺序**（延误时依次砍）：

1. 砍 DPO / GRPO
2. Player Simulator 砍到最小（只留老实玩家 + 反复无常玩家）
3. LLM 判分砍到只留人工抽查

**不许砍**：剧情完整可通关。一个玩不通的 demo 等于没有 demo。

**技术降级预案**：若芙兰的沉睡记忆召回始终不稳定，退化为「特定物品直接触发」的硬规则，保留玩法，牺牲机制优雅度。
